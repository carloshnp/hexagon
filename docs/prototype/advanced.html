Claude Code Headless Mode
Automação sem terminal interativo — CLI, cron jobs, e Python SDK

Headless mode é o Claude Code rodando de forma não-interativa: você passa o prompt via -p, o agente executa o loop completo (raciocínio, ferramentas, edições) e retorna o resultado via stdout. É a base para cron jobs, pipelines de dados, e integração com backends Python.

1.1  claude -p e --bare

# Forma básica — executa e imprime resultado
claude -p "O que faz o módulo auth.py?"

# Com ferramentas aprovadas automaticamente
claude -p "Encontre e corrija o bug em auth.py" --allowedTools "Read,Edit,Bash"

# --bare: sem auto-discovery de hooks/skills/MCP (recomendado para scripts)
claude --bare -p "Resuma este projeto" --allowedTools "Read"
bash
💡

--bare é o modo recomendado para scripts e CI. Sem ele, claude -p carrega hooks, skills, MCP servers e CLAUDE.md do diretório atual — o que pode variar entre máquinas. Com --bare, só o que você passar explicitamente via flags é carregado. Nota (Jun 2026): uso de claude -p e Agent SDK em planos de assinatura consome um crédito separado ("Agent SDK credit") a partir de 15/06/2026.

1.2  Output Formats

# Saída simples (texto puro)
claude --bare -p "Resuma o projeto"

# JSON — inclui session_id, cost, metadata
claude --bare -p "Resuma o projeto" --output-format json | jq '.result'

# JSON com schema tipado — structured_output no payload
claude --bare -p "Extraia os incidentes" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"incidents":{"type":"array","items":{"type":"string"}}}}' | \
  jq '.structured_output'

# Streaming — tokens em tempo real (útil para UI)
claude -p "Explique recursão" --output-format stream-json --verbose --include-partial-messages | \
  jq -rj 'select(.type == "stream_event" and .event.delta.type? == "text_delta") | .event.delta.text'

# Capturar session_id para reusar
SESSION=$(claude --bare -p "Revise o codebase" --output-format json | jq -r '.session_id')
claude -p "Agora foque nas queries de banco" --resume "$SESSION"
bash

1.3  Sessions no CLI

Sessões persistem o histórico de conversa em disco (~/.claude/projects/). Você pode retomá-las a qualquer momento — inclusive em runs separados de cron.

# Primeira chamada — captura session_id
SESSION=$(claude --bare -p "Análise inicial do dataset incidents.csv" \
  --allowedTools "Read,Bash" --output-format json | jq -r '.session_id')

# Continua a mesma sessão (mesmo contexto, mesmas ferramentas)
claude -p "Agora gere visualizações dos hotspots identificados" --resume "$SESSION"
claude -p "Crie o relatório ANALYSIS.md com todos os achados" --resume "$SESSION"

# Continua a ÚLTIMA sessão sem saber o ID
claude -p "Adicione recomendações de patrulhamento" --continue

1.4  Cron Job — Relatório Noturno

Exemplo completo: um script que baixa dados de ocorrências, passa pelo Claude e gera um relatório Markdown, executado toda noite via cron.

#!/bin/bash
# /usr/local/bin/rio-nightly-report.sh
set -euo pipefail

export ANTHROPIC_API_KEY="sk-ant-xxxx"   # ou use um secret manager
WORKSPACE="/srv/rio-safety"
TODAY=$(date +%Y-%m-%d)
REPORT="$WORKSPACE/reports/REPORT_$TODAY.md"

# Baixar dados mais recentes da cidade
curl -sf "https://dados.rio/api/ocorrencias?date=$TODAY" \
  -o "$WORKSPACE/data/incidents_$TODAY.json"

# Pipe dados → Claude → arquivo de relatório
cat "$WORKSPACE/data/incidents_$TODAY.json" | \
  claude --bare -p \
    "Analise estes registros de ocorrências do Rio de Janeiro para $TODAY.
     Gere REPORT.md com: resumo executivo, top 3 bairros críticos,
     tendências, prioridades de patrulhamento recomendadas.
     NUNCA inclua nomes, CPF ou endereços nas saídas." \
    --allowedTools "Read" \
    --output-format json | \
  jq -r '.result' > "$REPORT"

echo "[$TODAY] Relatório: $REPORT"
rio-nightly-report.sh
# Adicionar ao crontab (crontab -e)
# Toda noite às 2h, log em /var/log/rio-agent.log
0 2 * * * /usr/local/bin/rio-nightly-report.sh >> /var/log/rio-agent.log 2>&1

from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage, SystemMessage

async def run_once():

from claude_agent_sdk import ClaudeSDKClient, AssistantMessage, TextBlock, ResultMessage

# ClaudeSDKClient — multi-turn, contexto compartilhado entre mensagens
async def multi_turn():
    async with ClaudeSDKClient() as client:
        # Primeira pergunta
        await client.query("Leia o arquivo incidents.json e identifique padrões")
        async for msg in client.receive_response():
            if isinstance(msg, AssistantMessage):
                for block in msg.content:
                    if isinstance(block, TextBlock):
                        print(block.text)

        # Follow-up mantém contexto completo
        await client.query("Agora gere visualizações dos hotspots encontrados")
        async for msg in client.receive_response():
            if isinstance(msg, ResultMessage):
                print(f"Done. Custo: ${msg.total_cost_usd:.4f}")

1.6  Session Manager — Classe Reutilizável

Classe que encapsula criação, retomada, tagging e listagem de sessões. Importe diretamente no seu FastAPI ou script de pipeline.

"""rio_agent.py — Gerenciador de sessões reutilizável."""
import asyncio
from claude_agent_sdk import (
    query, ClaudeAgentOptions,
    list_sessions, rename_session, tag_session,
    SystemMessage, ResultMessage,
)

class RioAgent:
    """Sessão Claude reutilizável para o dashboard de segurança."""

    def __init__(self, workspace: str = ".", model: str = "claude-sonnet-4-6"):
        self.workspace = workspace
        self.model = model
        self._session_id: str | None = None

    async def run(self, prompt: str, tools: list[str] | None = None) -> tuple[str, float]:
        """Executa um prompt. Retorna (resultado, custo_usd)."""
        opts = ClaudeAgentOptions(
            cwd=self.workspace, model=self.model,
            allowed_tools=tools or ["Read", "Bash"],
            permission_mode="acceptEdits",
        )
        result, cost = "", 0.0
        async for msg in query(prompt=prompt, options=opts):
            if isinstance(msg, SystemMessage) and msg.subtype == "init":
                self._session_id = msg.data["session_id"]
            if isinstance(msg, ResultMessage):
                result = msg.result
                cost = msg.total_cost_usd or 0.0
        return result, cost

    async def resume(self, prompt: str) -> tuple[str, float]:
        """Continua a sessão mais recente com contexto completo."""
        if not self._session_id:
            return await self.run(prompt)
        opts = ClaudeAgentOptions(resume=self._session_id)
        result, cost = "", 0.0
        async for msg in query(prompt=prompt, options=opts):
            if isinstance(msg, ResultMessage):
                result = msg.result; cost = msg.total_cost_usd or 0.0
        return result, cost

    def tag(self, label: str) -> None:
        if self._session_id: tag_session(self._session_id, label)

    def rename(self, title: str) -> None:
        if self._session_id: rename_session(self._session_id, title)

    def list_recent(self, n: int = 5):
        return list_sessions(directory=self.workspace, limit=n)

    @property
    def session_id(self) -> str | None:
        return self._session_id


# Uso em FastAPI
async def generate_report(date: str) -> str:
    agent = RioAgent(workspace="/srv/rio-safety")
    result, cost = await agent.run(
        f"Gere o relatório de ocorrências para {date}. NUNCA inclua PII.",
        tools=["Read", "Write"]
    )
    agent.tag("report")
    agent.rename(f"Relatório {date}")
    print(f"Custo: ${cost:.4f}")
    return result

import subprocess, json
from pathlib import Path

INCIDENT_SCHEMA = {
    "type": "object",
    "properties": {
        "incidents": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "bairro":     {"type": "string"},
                    "tipo":       {"type": "string"},
                    "severidade": {"type": "string", "enum": ["baixa", "media", "alta"]},
                    "quantidade": {"type": "integer"}
                },
                "required": ["bairro", "tipo", "severidade", "quantidade"]
            }
        },
        "hotspots": {"type": "array", "items": {"type": "string"}},
        "resumo":   {"type": "string"}
    },
    "required": ["incidents", "hotspots", "resumo"]
}

def extract_incidents(input_path: Path, output_path: Path) -> dict:
    with open(input_path) as f:
        proc = subprocess.run(
            ["claude", "--bare", "-p",
             "Extraia e categorize as ocorrências. NUNCA inclua PII.",
             "--output-format", "json",
             "--json-schema", json.dumps(INCIDENT_SCHEMA)],
            stdin=f, capture_output=True, text=True, check=True
        )
    payload = json.loads(proc.stdout)
    output_path.write_text(json.dumps(payload["structured_output"], ensure_ascii=False, indent=2))
    return {"session_id": payload["session_id"], "hotspots": payload["structured_output"]["hotspots"]}

# Uso
result = extract_incidents(Path("data/raw.txt"), Path("data/incidents_typed.json"))
print("Hotspots:", result["hotspots"])

Hooks
Lógica customizada em cada etapa do ciclo de vida do agente

Hooks são listeners de eventos que executam código customizado em momentos específicos do pipeline do Claude Code — antes de um tool rodar, depois que um arquivo é editado, quando o agente termina, etc. Configurados em .claude/settings.json ou via Python SDK.

2.1  Lifecycle Events

EventoFaseDescrição & uso típico
PreToolUse⬆ AntesRoda antes de qualquer ferramenta. Pode bloquear ou modificar a chamada — ideal para auditoria e validação.
PostToolUse⬇ DepoisRoda após a ferramenta completar. Perfeito para auto-formatação de código editado e logging.
Stop🏁 FimRoda quando Claude termina de responder. Use para notificações (notify-send, webhook).
SessionStart🚀 InícioRoda uma vez ao iniciar a sessão. Útil para preparar ambiente, log de início.
SessionEnd🔚 FimRoda ao fechar a sessão. Para cleanup, envio de sumário.
UserPromptSubmit📝 InputRoda quando o usuário submete uma mensagem. Pode modificar ou enriquecer o prompt.
PreCompact🗜 MemóriaRoda antes de compactar o contexto. Injete contexto crítico que não deve ser perdido.
Notification🔔 BGClaude envia notificação assíncrona de progresso.
SubagentStart🤖 SubQuando um sub-agente é iniciado. Para rastrear execuções paralelas.
SubagentStop🤖 SubQuando um sub-agente termina. Consolide resultados ou acione revisão.

2.2  Tipos de Hook

command
Shell Command
Executa um script ou binário. Variáveis de ambiente do Claude disponíveis: $CLAUDE_TOOL_FILE_PATH, $CLAUDE_TOOL_COMMAND, $CLAUDE_CWD.
prompt
Instrução Natural
Envia uma instrução em linguagem natural de volta ao Claude. Ex: "Revise este arquivo por vulnerabilidades de segurança antes de salvar."
agent
Sub-agente
Spawna um sub-agente especializado para lidar com o evento. Ex: um revisor de segurança automático a cada edit.
http
Webhook HTTP
Faz um request HTTP para um endpoint externo. Integração com Slack, Discord, sistemas de monitoramento.

2.4  Hooks no Python SDK

from claude_agent_sdk import query, ClaudeAgentOptions, HookMatcher
from pathlib import Path
from datetime import datetime

async def audit_file_changes(input_data, tool_use_id, context):
    """Loga cada edição de arquivo em audit.log."""
    fp = input_data.get("tool_input", {}).get("file_path", "unknown")
    Path("audit.log").open("a").write(f"{datetime.now().isoformat()} EDIT {fp}\n")
    return {}

async def block_dangerous_commands(input_data, tool_use_id, context):
    """Bloqueia comandos destrutivos."""
    cmd = input_data.get("tool_input", {}).get("command", "")
    if "rm -rf" in cmd or "--force" in cmd:
        return {"decision": "block", "reason": "Comando destrutivo bloqueado pelo hook"}
    return {}

opts = ClaudeAgentOptions(
    permission_mode="acceptEdits",
    hooks={
        "PostToolUse": [HookMatcher(matcher="Edit|Write", hooks=[audit_file_changes])],
        "PreToolUse": [HookMatcher(matcher="Bash", hooks=[block_dangerous_commands])],
    }
)

MCP Servers para o Dashboard de Segurança
Conecte Claude a bancos de dados, APIs e sistemas externos via Model Context Protocol

MCP servers expõem ferramentas externas ao Claude dentro da sessão. Para o dashboard de segurança do Rio, os mais úteis são: SQLite (query direto no banco), Filesystem (arquivos fora do projeto), HTTP/Fetch (APIs da cidade) e Git (histórico do código).

⚠️

Tool ceiling: Claude Code suporta até ~50 ferramentas ativas entre todos os MCP servers. Acima disso, o modelo começa a escolher a ferramenta errada. Instale apenas os servidores que você vai usar na sessão atual — use --mcp-config para passar configs específicas por script.

3.2  Servidor MCP Customizado — APIs do Rio

Crie um servidor MCP em ~30 linhas para expor endpoints específicos da Prefeitura Rio como ferramentas nativas do Claude:

# mcp_servers/rio_city_api.py
from mcp.server.fastmcp import FastMCP
import httpx

mcp = FastMCP("rio-city-api")

@mcp.tool()
async def get_incidents(date: str, bairro: str = "") -> str:
    """Busca ocorrências na API da Prefeitura do Rio."""
    params = {"date": date}
    if bairro: params["bairro"] = bairro
    async with httpx.AsyncClient() as c:
        r = await c.get("https://dados.rio/api/ocorrencias", params=params, timeout=10)
    return r.text

@mcp.tool()
async def get_camera_coverage(bairro: str) -> str:
    """Retorna cobertura de câmeras por bairro."""
    async with httpx.AsyncClient() as c:
        r = await c.get(f"https://dados.rio/api/cameras?bairro={bairro}", timeout=10)
    return r.text

if __name__ == "__main__":
    mcp.run()

Skill Selection — Evitando Context Bloat
Mais skills não significa mais performance — precisão supera volume

5.1  O Problema do Tool Ceiling

O Claude Code tem um teto de ~50 ferramentas ativas (entre skills, MCP servers e built-ins). Acima disso, o modelo começa a escolher a ferramenta errada com mais frequência — não por incapacidade, mas porque precisa raciocinar sobre um espaço de opções muito grande.

🚨

Regra prática: 3–5 skills altamente relevantes batem 20 skills genéricas. Instale por workspace (não globalmente), use path-scoping, e remova skills que não vai usar no hackathon.

5.2  Context Rot — Como Arquivos de Skill Degradam o Agente

Context rot é a degradação gradual do agente causada por skill files muito grandes, densos ou cheios de informação desnecessária. Um arquivo de skill inchado degrada a performance mesmo quando está bem dentro do limite de tokens — porque aumenta o ruído relativo às instruções relevantes.

❌ Degrada performance✅ Melhora performance
Skills globais instaladas para "ter disponível"Skills instaladas apenas no workspace que as usa
SKILL.md com 500+ linhas de exemplosSKILL.md focado: role + fases + failure conditions
20 skills ativas sem path-scoping5 skills com paths: bem definidos
Skill genérica que tenta cobrir tudoSkill single-responsibility (EDA separado de ML separado de viz)
Triggers amplos: "analyze", "process data"Triggers específicos: "run EDA", "fit sklearn model"

6.4  Anatomia de um SKILL.md de Data Science

Um SKILL.md eficaz tem 3 camadas: descrição/triggers (o que ativa), instruções com casos limite (o que fazer), ferramentas/scripts (como fazer de forma determinística).

---
name: eda-tabular
description: "EDA completo para dados tabulares CSV/DataFrame."
version: "1.0.0"
triggers:
  - run EDA
  - explore dataset
  - analyze data quality
  - check data
tools:
  - python_repl
  - create_file
paths: ["data/**", "notebooks/**"]
---

## Role
Senior data scientist. Execute EDA completo ao ser ativado.

## Fases (execute nesta ordem)
1. **Load & Validate** — inferir tipos, checar shape, detectar encoding issues
2. **Univariate** — distribuições, missing (%), outliers (IQR + z-score),
         normalidade (Shapiro-Wilk se n<5000, KS se n>=5000)
3. **Multivariate** — correlação (Pearson + Spearman), pairplot (top 8 features por variância),
         VIF para multicolinearidade
4. **Visualizações** — salvar em docs/charts/: histogramas, boxplots, heatmap, pairplot
5. **Relatório** — escrever docs/ANALYSIS.md com findings + recomendações de modelagem

## Failure Conditions
- NUNCA assumir normalidade sem testar
- Se missing > 40% em uma coluna: flag para remoção, NÃO imputar
- Se n < 30: aviso de poder estatístico baixo
- NUNCA expor PII (nomes, CPF, endereços) nos outputs ou gráficos

## Output
```
# EDA Report — {dataset_name}
## Shape & Types | ## Missing | ## Univariate | ## Multivariate | ## Recomendações
```
skills/eda-tabular/SKILL.md
