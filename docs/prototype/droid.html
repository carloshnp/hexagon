Um agente de IA de terminal completo — pair programming, geração de repos inteiros, agentes autônomos e orquestração multi-agente. Usado no hackathon via OpenRouter para geração de código mais barata e rápida.

1
Visão Geral / Overview
O que é o Droid e por que usá-lo no hackathon

Droid é um agente de IA de terminal desenvolvido pela Factory AI. Ele funciona tanto como parceiro de pair programming em tempo real quanto como agente autônomo para tarefas complexas — geração de repos inteiros, refatorações grandes, revisões de código e orquestração multi-agente via Missions.

No hackathon, ele complementa o Claude Code: use Droid + OpenRouter para tarefas de geração de código intensivas em tokens (scaffolding completo, escrever módulos inteiros, gerar testes em massa), aproveitando modelos mais baratos via OpenRouter. Use Claude Code para iteração e decisões arquiteturais.

🤖 Droid — Use para
  • Gerar repos e módulos inteiros de uma vez
  • Pair programming com modelos baratos (OpenRouter)
  • Missions: orquestração multi-agente paralela
  • Tarefas autônomas longas sem supervisão constante
  • Code review + security review automatizados
  • Quando os $50 do Claude Code estiverem acabando
⚡ Claude Code — Use para
  • Iteração rápida e decisões arquiteturais
  • Fluxo Spec Doc (prompt → SPEC.md → código)
  • Skills do ecossistema (ECC, geoai, feynman)
  • Integração com MCP servers complexos
  • Quando precisar de Claude Sonnet/Opus especificamente
💡 Regra do hackathon Use o Droid com um modelo barato do OpenRouter (ex: DeepSeek ou Gemini) para gerar scaffolding e código boilerplate. Isso economiza seus créditos Claude Code para as iterações mais refinadas que precisam do Sonnet.

BYOK: Configurando OpenRouter
Bring Your Own Key — sua chave, sua API, seus modelos

BYOK permite usar sua própria chave do OpenRouter no Droid. Sua chave fica apenas no seu computador — nunca é enviada para os servidores da Factory. Isso dá acesso a dezenas de modelos via uma única API.

🔒 Segurança As chaves ficam em ~/.factory/settings.json (Linux) ou %USERPROFILE%\.factory\settings.json (Windows). Use variáveis de ambiente via ${VAR_NAME} para não expor a chave diretamente no arquivo.

Passo a Passo / Step by Step

1
Crie uma conta no OpenRouter
Acesse openrouter.ai, crie uma conta e adicione créditos. Navegue para openrouter.ai/keys e crie uma API key.
2
Salve a chave como variável de ambiente
Recomendado para não expor a chave no arquivo de config:
# Linux / macOS
export OPENROUTER_API_KEY="sk-or-v1-..."
echo 'export OPENROUTER_API_KEY="sk-or-v1-..."' >> ~/.bashrc

# Windows PowerShell
[System.Environment]::SetEnvironmentVariable("OPENROUTER_API_KEY", "sk-or-v1-...", "User")
shell

8
Missions
Orquestração multi-agente para geração de projetos completos

Missions são fluxos de trabalho estruturados para projetos grandes. Em vez de uma sessão linear, você colabora com o Droid para criar um plano com milestones, depois uma camada de orquestração distribui o trabalho entre múltiplos agentes em paralelo.

🎯 O valor principal está no planejamento A documentação da Factory enfatiza: "o maior valor encontrado nas Missions está na fase de planejamento." Um plano bem estruturado com milestones claros produz resultados muito melhores do que mergulhar direto na execução.

Como Funciona / How It Works

1
Iniciação
Execute /missions em qualquer sessão do Droid para entrar no modo Mission.
2
Planejamento colaborativo
O Droid faz perguntas clarificadoras, identifica constraints, e constrói um plano com você. Features são organizadas em milestones — cada um representa um checkpoint significativo.
3
Aprovação do plano
Você revisa o plano completo. Ajuste, adicione ou remova features antes de aprovar. Não aprove até estar satisfeito — mudanças no meio da execução são custosas.
4
Execução orquestrada
Feature workers executam cada feature (~1 run por feature). Validation workers revisam cada milestone. Você monitora, desbloqueia impedimentos e redireciona se necessário.
5
Intervenção quando necessário
Pause o orquestrador para replanear, reatribuir tarefas travadas, ou ajustar o escopo. Você é o gerente de projeto — não o executor.

Exemplo: Mission para o Hackathon

# Inicie uma Mission com este prompt de kickoff:

Build a complete public safety analytics MVP for Rio de Janeiro.

Tech stack: FastAPI + SQLite (backend), React + Vite + Leaflet (frontend).

Features needed:
1. CSV data ingestion pipeline (crime occurrence data with lat/lon)
2. REST API with filtering by date, crime type, and neighborhood
3. Statistical aggregation endpoints (by type, by neighborhood)
4. Anomaly detection: flag neighborhoods >2 std devs above average
5. React frontend with Leaflet heatmap + filter panel + stats chart
6. Pytest test suite for all API endpoints

Constraints:
- Must work offline with local CSV files
- No PII in any API response
- MVP scope: get it working, not perfect
- Target: 4 hours of execution time

Create milestones: Data Layer → API → Anomaly Detection → Frontend → Tests
mission kickoff prompt

Importando Configs do Claude Code
Guia completo de tradução — agentes, CLAUDE.md, commands e settings

O Droid tem importação nativa de agentes do Claude Code. Para outros arquivos (CLAUDE.md, commands, settings), a tradução é manual mas direta. O objetivo é reutilizar o trabalho já feito no Claude Code sem reescrever tudo do zero.

10.1 Importação Nativa de Agentes / Native Agent Import

O único arquivo importado automaticamente pelo Droid é o formato de agentes do Claude Code (.claude/agents/). O processo converte agent → droid com mapeamento de modelo e ferramentas. 

# Dentro do Droid:
/droids
# Pressione I para abrir o importador
# → Escaneia automaticamente:
#   Projeto:  .claude/agents/
#   Pessoal:  ~/.claude/agents/
# → Use Space para selecionar, A para todos, Enter para importar
# → Droids importados vão para ~/.factory/droids/ (pessoal)
droid — importação nativa
⚠️ Mapeamento de ferramentas Ferramentas do Claude Code são mapeadas para equivalentes do Factory. Algumas podem gerar avisos de validação se não tiverem equivalente direto — revise os droids importados e substitua manualmente se necessário.
Ex: Claude Code Write → Factory Create · Claude Code Edit → Factory Edit

# Script de migração em lote / Batch migration script
# Converte todos os commands do Claude Code em skills do Droid

mkdir -p .factory/skills

for cmd_file in .claude/commands/*.md; do
  name=$(basename "$cmd_file" .md)
  mkdir -p ".factory/skills/$name"
  cp "$cmd_file" ".factory/skills/$name/skill.md"
  echo "Migrated: $name"
done

echo "Done. Review each skill in .factory/skills/ for compatibility."
